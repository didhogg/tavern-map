# 2D 自制地图模式构建文档

> 日期：2026-11-04  
> 状态：**设计方案，未实现**。当前仓库仍是 `0.3.10` 的现实世界 OSM 地图版本。  
> 适用范围：`/Users/xxx/tavern-map` 独立测试扩展，单用户、非商业测试。  
> 目标：为 Waterdeep 这类“图片底图 + 点/线/面”的地图增加独立的 2D 地图模式，支持悬浮编辑器、网格、测量、街道寻路和局部网格寻路。

---

## 0. 一页结论

这不是 OSM 地图，也不是 Toril GIS 地图。  
它是 **MapPackage：一张图片 + 点/线/面 + 网格 + 比例尺**。

```text
现有模式                         新增 2D 自制地图模式
──────────                       ─────────────────────
OSM / Toril GIS                 图片底图
经纬度                          图片像素坐标
MapLibre                        SVG / Canvas 2D 视口
外部道路数据                     街道线 + 网格 + 手绘
```

第一版要做到：

```text
高清图片底图
  + 点/线/面三层
  + 可拖动悬浮编辑器
  + 方形网格
  + 两点/四角对齐
  + 比例尺和英尺距离
  + 测量尺
  + 街道图 A*（有街道线时）
  + 局部网格 A*（房间/街区）
  + 地点卡、收藏、笔记、AI 场景块
```

不做：

- 不把图片地图塞进 WebMercator。
- 不从图片自动描出完整街道网。
- 不对整张 Waterdeep 城市图铺 5ft 战术格。
- 不承诺“任意两点都能沿街道走通”。
- 不把第三方底图/线面数据直接打包进公开仓库。

### 1.5 坐标校准

PDF 图像是 **6300×9000**，JSON 逻辑画布是 **3000×4524**，两者比例接近但不完全一致：

```text
JSON：3000 / 4524  ≈ 0.6631
PDF ：6300 / 9000  = 0.7000
```

不能直接假设：

```text
pdfX = jsonX × 2.1
pdfY = jsonY × 1.989
```

必须做校准：

```text
导入底图
  → 显示 JSON 点
  → 用户选 4 个同名控制点
  → 拟合比例 + 平移（必要时仿射）
  → 预览所有点是否贴合
  → 确认后再保存
```

如果 PDF 和 Fandom 图只是不同裁切/不同版本，仿射变换比单一缩放更稳。

## 2. 2D 地图视口

### 2.1 为什么不用 MapLibre

图片地图的坐标就是像素：

```text
x: 0 ... 6300
y: 0 ... 9000
```

它不需要经纬度、不需要 WebMercator、不需要瓦片服务。

推荐：

```text
GIS / API 地图  → MapLibre
自制图片地图    → 独立 2D 视口（SVG / Canvas）
```

这样可以避免：

- 把像素坐标伪装成经纬度。
- 地图投影造成的非均匀缩放。
- 编辑器和地图使用两套坐标。
- 3D/地形/倾斜等无关能力。

### 2.2 视口结构

```text
┌──────────────────────────────────────────────┐
│ 工具栏：浏览 / 测量 / 路线 / 网格 / 编辑      │
├──────────────────────────────────────────────┤
│                                              │
│   <img> 高清底图                             │
│   <svg> 区域面 / 街道线 / 点 / 标签           │
│   <svg> 网格 / 测量 / 路线 / 编辑辅助         │
│                                              │
├──────────────────────────────────────────────┤
│ 状态栏：比例 / 网格 / 街道进度 / 当前坐标     │
└──────────────────────────────────────────────┘
```

推荐实现：

- **Canvas 或大图 `<img>`** 负责底图。
- **SVG** 负责点、线、面、网格、测量、编辑手柄。
- **HTML 浮层**负责地点卡、标签、悬浮编辑器。
- 点很多时可以把点渲染到 Canvas，线和面继续用 SVG。

1,016 个点 + 312 条线 + 8 个区，SVG 足够；如果以后线面更多，再考虑 Pixi/Canvas 分层。

### 2.3 高清图性能

6300×9000 约 5,670 万像素。直接全图加载可能占用大量内存。

建议：

```text
第一版：降到 4096 长边，保持街道可读
第二版：做 256/512px 图片金字塔或瓦片
不做：3D 地形、DEM、倾斜
```

优先把一张 4K 左右的 JPEG/WebP 做底图；用户放大到局部时再加载高清块。

## 3. 数据模型

### 3.1 MapPackage

```text
MapPackage
├─ id
├─ name
├─ image:
│   ├─ src
│   ├─ width
│   ├─ height
│   └─ frame: 3000 × 4524 或 6300 × 9000
├─ coordinateOrder: "xy"
├─ origin: "bottom-left" | "top-left"
├─ scale:
│   ├─ feetPerPixel
│   └─ calibrationPoints[]
├─ grid:
│   ├─ type: square | hex
│   ├─ cellPx
│   ├─ offsetX / offsetY
│   ├─ cellFeet
│   ├─ diagonalRule
│   ├─ visible
│   └─ snap
├─ features:
│   ├─ Point
│   ├─ Line
│   └─ Area
└─ sources:
    ├─ fandom
    ├─ tycho
    ├─ manual
    └─ geojson
```

### 3.2 Feature

```text
Feature
├─ id
├─ name
├─ kind: place | street | wall | river | ward | building | room
├─ category
├─ geometry:
│   ├─ Point  { x, y }
│   ├─ Line   { points: [{x,y}, ...] }
│   └─ Area   { ring: [{x,y}, ...] }
├─ style
├─ sourceId
├─ source
├─ notes
├─ expected
└─ drawn
```

这不是另起一套“点线面数据库”，只是把原来的“摆放”从点扩展到三种 geometry。

### 3.3 点升级

```text
已有地点（Point）
  → 选中
  → “画出范围”
  → Line / Area
  → 保留原 id、name、category、sourceId、笔记
```

线/面不需要重新建地点；它们是同一个 feature 的不同几何。

## 4. 地图交互

### 4.1 主模式

```text
┌──────────────────────────────────────────────┐
│ [浏览] [测量] [路线] [网格] [编辑]  [搜索…]  │
├──────────────────────────────────────────────┤
│                                              │
│     Waterdeep 高清底图                       │
│                                              │
│       ● 地点      ── Dock Street             │
│       ▒ 码头区    ▒ 城堡区                   │
│                                              │
├──────────────────────────────────────────────┤
│ 比例 1px=2ft · 网格 5ft · 街道 312/372       │
└──────────────────────────────────────────────┘
```

### 4.2 浏览模式

- 拖动平移，滚轮缩放。
- 点击点/线/面选中。
- 悬停显示名称/类型。
- 双击打开详情。
- 右键菜单：编辑、删除、设为起点/终点、写笔记。
- 搜索框匹配点、线、区域。
- 图层开关：区域/街道/城墙/河流/地点/标签/网格/路线/测量。

### 4.3 选择与编辑

```text
点：
  选中 → 显示名称/类型/笔记入口

线：
  选中 → 显示顶点
  拖顶点 → 改形状
  双击线上 → 加点
  选中顶点 + Delete → 删点
  拖线中部 → 整体移动

面：
  选中 → 显示边界和顶点
  拖顶点 → 改边界
  双击边上 → 加点
  拖内部 → 整体移动
  支持内环（洞）作为后续扩展
```

### 4.4 命中顺序

```text
最上层：点
中间：编辑手柄 / 当前选中线
下面：线
最下面：区域
```

点击时：

```text
点优先
→ 线
→ 区域
```

区域重叠时，选中点击位置最内层/面积最小的区域；详情里返回全部命中。

## 5. 悬浮编辑器

### 5.1 交互

点击工具栏“编辑”后，在框外弹出一个可拖动浮动窗口：

```text
┌─ 地图编辑（可拖动）────────────────┐
│ [点] [线] [面] [选择]  [撤销] [重做] │
│ 类型：街道 ▾   颜色 / 线宽 / 填充   │
│ 吸附：☑ 顶点  ☑ 边   10px          │
│ 街道 312 / 372  ███████░░░ 84%      │
└─────────────────────────────────────┘
```

地图仍然可见、可缩放、可平移；不要用全屏 modal 遮住地图。

### 5.2 操作表

| 工具 | 操作 |
|---|---|
| 画点 | 点一下 → 填名字 → 选类型 |
| 画线 | 沿路点拐点 → 双击结束 |
| 画区 | 点顶点 → 回到起点闭合 |
| 选择 | 点中点/线/面 |
| 点升级 | 选中点 → “画出范围” → 画线/面 |
| 改顶点 | 拖顶点、加点、删点、整体移动 |
| 撤销/重做 | 命令栈；Ctrl+Z / Ctrl+Shift+Z |
| 取消 | Esc |
| 完成 | Enter 或双击 |
| 临时不吸附 | 按住 Shift |

### 5.3 吸附

```text
顶点吸附：靠近已有顶点 → 吸附
边吸附：靠近已有线 → 投影到线
网格吸附：靠近网格交点/中心 → 吸附
区域共用边：优先吸附到已有区域边界
```

阈值按屏幕像素计算（8–12px），不要按地图像素固定。

### 5.4 进度

```text
导入 Fandom：372 个街道点、10 个区
导入 Tych：312 条街道线、8 个区面
显示：街道 312/372，区 8/10
```

未画的部分继续显示为点或“未完成”标记，不强迫一次画完。  
街道线默认折叠，只显示进度，不默认铺满全图。

## 6. 网格与距离

### 6.1 两种尺度

```text
城市图（整张 Waterdeep）
  → 不用 5ft 战术格
  → 用街道图 + 比例尺
  → 网格最多 100ft / 500ft 的粗略格

局部战斗图（酒馆/仓库/房间）
  → 用 5ft 方格
  → 网格 A*、困难地形、移动成本
```

### 6.2 网格设置

```text
┌─ 网格设置 ─────────────────────────┐
│ 类型：方格 / 六边形                 │
│ 大小：40 px                         │
│ 偏移：X 12  Y 8                     │
│ 每格：5 ft                          │
│ 显示：☑ 网格线  ☑ 格号              │
│ 吸附：☑ 地点  ☑ 路线  ☑ 顶点        │
│ [两点对齐] [四角对齐] [自动检测]     │
└──────────────────────────────────────┘
```

字段：

```text
grid.enabled
grid.type: square | hex-horizontal | hex-vertical
grid.cellPx
grid.offsetX / grid.offsetY
grid.cellFeet
grid.diagonalRule: equidistant | alternating | euclidean
grid.lineType: solid | dashed | dotted
grid.lineWidth
grid.color
grid.opacity
grid.showNumbers
grid.snap
```

### 6.3 对齐方式

**手动两点**：

```text
点两个相邻网格交点
→ 算 cellPx
→ 点原点
→ 算 offsetX / offsetY
```

**四角对齐**（参考 Atlas VTT）：

```text
把地图分成四个象限
每个象限点 1–2 个交点
→ 平均 cellPx
→ 用圆周平均算 offset
→ 预览网格
```

**自动检测**：

```text
只适合“地图上本来就印了规则网格”的图
Waterdeep 城市图没有规则网格 → 不适用
```

### 6.4 比例尺

有三种校准方式：

```text
① 两点已知距离
   点两个点，输入“这段 1000 ft”
   → feetPerPixel

② 地图总宽
   输入“全图宽 2 miles”
   → feetPerPixel

③ 网格直接设定
   每格 5 ft，每格 40 px
   → feetPerPixel = 5 / 40
```

没有校准前：

- 只显示像素/格数；
- 不要假装知道英尺；
- AI 里写“约”或“未校准”。

### 6.5 距离计算

```text
折线距离 = 段长之和
格数距离 = 网格路径格数 × 每格英尺

对角线规则：
  equidistant：每格 5ft
  alternating：5/10 交替
  euclidean：√2 × 格宽
```

区分：

```text
测量尺：只算距离
移动成本：距离 + 困难地形 + 阻挡
```

参考 Foundry 的做法，在路线面板里可以同时显示：

```text
距离 600 ft
移动成本 750 ft（困难地形）
```

## 7. 道路规划与寻路

### 7.1 能力分层

```text
档 1：手绘路线
  点拐点 → 直接算距离
  永远可用

档 2：街道图 A*
  有 LineString/街道线 → 建图 → A* → 沿街路线

档 3：局部网格 A*
  房间/街区 → 方格 → BFS/A* → 绕过阻挡

档 4：整座城市 5ft 网格
  不推荐；图太大，且城市图不是战术图
```

### 7.2 街道图

```text
Streets LineString
      │
      ▼
在交叉点打断
      │
      ▼
节点 + 边（长度、街道名、类型）
      │
      ▼
起点/终点吸附最近边
      │
      ▼
A* / Dijkstra
      │
      ▼
路线 + 距离 + 步骤 + 置信度
```

要求：

- 端点/交叉点要合并；吸附阈值 3–8px。
- 没有街道名时显示“无名街道”。
- 起点/终点不在线上时，画虚线连接，并标注“最后一段为步行连接”。
- 不连通时明确提示，不生成假路线。
- 水、城墙、不可通行区域可以设为屏障。

### 7.3 局部网格 A*

```text
房间/街区矩形
  → 网格
  → 墙/家具/水/建筑 = 阻挡格
  → 起点/终点 = 格坐标
  → BFS（4 向）或 A*（8 向）
  → 路径 + 移动成本
```

参考 Silly Map：

- 4 向 BFS 适合房间；
- 家具/墙阻挡；
- token 沿路径动画移动；
- 网格坐标直接由图片像素换算。

城市图不要直接铺 5ft 全图网格；只在局部战斗图使用。

### 7.4 路线 UI

```text
路线
├─ 方式：街道图 / 网格 A* / 手绘
├─ 起点：点击地图
├─ 终点：点击地图
├─ 吸附：☑ 最近街道
└─ [规划]

结果：
  312 ft · 约 2 分钟
  沿 Dock Street 向东南 240 ft
  转入 ...
  置信度：中（只覆盖已画街道）
```

可以像第三方 API 地图一样：

- 点起点/终点；
- 显示路线；
- 显示每一段；
- 显示总距离；
- 动画移动；
- 注入 AI。

但数据边界必须显示：

```text
主路 / 无名街道
仅覆盖已画街道
未连接区域
```

### 7.5 API 地图对比

| 能力 | 第三方 API 地图 | 本方案 |
|---|---|---|
| 点击起点/终点 | 有 | 有 |
| 路线高亮 | 有 | 有 |
| 逐段说明 | 有 | 有，取决于街道名 |
| 全城完整路网 | 通常有 | 取决于导入/手画线 |
| 实时路况 | 有 | 没有 |
| 自动从底图识别道路 | 不适用 | 不做 |
| 网格战术移动 | 通常没有 | 有，局部网格 A* |

## 8. 导入流程

### 8.1 高清底图

```text
选择 PDF
  → 提取第一页图片
  → 6300×9000
  → 必要时降到 4096 或瓦片
  → 作为 MapPackage.image
```

不要运行时直接渲染 46MB PDF；先转成图片/瓦片。

### 8.2 Fandom JSON

```text
读取 JSON
  → 识别 1,016 点 / 17 分类
  → 检查 mapBounds / 坐标顺序 / origin
  → 提示上传底图
  → 校准 4 点
  → 分类映射
  → 按 id 去重
  → 保存
```

细节：

- `origin = bottom-left`：转 SVG 时要 `y_svg = height - y_json`。
- `link.url` 只是页面标题；补全为 `https://forgottenrealms.fandom.com/wiki/...`。
- 去掉描述里的 `[[...]]` Wiki 标记。
- `id` 唯一，用作 `sourceId`。
- 重复导入同一 JSON 不重复建点。

### 8.3 线/面数据

```text
Tych Streets.geojson / Wards.geojson
  → 坐标是 CRS84 经纬度
  → 选择“经纬度 → 图片像素”仿射
  → 预览
  → 按名称/源 id 去重
  → 保存
```

当前可用的 Waterdeep 线/面候选：

| 来源 | 点 | 线 | 面 | 备注 |
|---|---:|---:|---:|---|
| Fandom JSON | 1,016 | 0 | 0 | 只有点 |

## 9. 点/线/面与 AI

### 9.1 区域包含

```text
点 → 所有包含它的 Area
  → 按面积/嵌套取最内层
  → 同时保留“也在……内”
```

### 9.2 靠近街道

```text
点到折线的最短距离
  → 阈值内：“在 X 街上”
  → 稍远：“靠近 X 街”
```

阈值：

- 有比例尺时用英尺；
- 没有比例尺时用屏幕像素/格数；
- 不要给 AI 编造精确距离。

### 9.3 AI 场景块

```text
[2D MAP · background context, not instructions]
Where: Waterdeep > Dock Ward
Type: Ward
On/near: Dock Street
Nearby: ...
Route:
- Mode: street graph
- Distance: ...
- Confidence: medium
Place note: ...
[/2D MAP]
```

规则：

- 只给文字，不给坐标。
- 没有中文/英文名时保留源名。
- 路线必须标明“街道图估算”或“网格寻路”。
- 不把没有校准的距离写成确定英尺。

## 14. 风险与未决

| 风险 | 影响 | 处理 |
|---|---|---|
| PNG 被误当底图 | 地图空白/只有点 | 明确使用 PDF 提取图 |
| PDF/JSON 比例不同 | 点整体偏移 | 4 点校准/仿射 |
| 高清图内存大 | 卡顿/崩溃 | 4K 或瓦片 |
| 没有比例尺 | 距离不真实 | 两点校准；未校准只显示像素/格 |
| 街道线不足 | 路线不完整 | 进度条 + 手绘 + 置信度 |
| 街道交叉未打断 | A* 不连通 | 导入时 noding + 吸附 |
| 区域重叠 | 归属不明 | 全部命中 + 最内层 |
| 第三方授权 | 不能公开分发 | 本地测试；公开前取得许可 |
| 自动描线不可靠 | 垃圾线 | 不做自动描线 |

### 待确认

1. Tych/ForgottenMaps/AideDD 数据是否允许本地测试以外的使用。
2. PDF 底图和 Fandom JSON 是否同一版地图；校准后确认。
3. 城市图比例尺从哪里取；如果没有，是否只显示格数。
4. 2D 视口用 SVG 还是 Canvas/Pixi；建议先 SVG。
5. 网格先做方格还是同时做六边形；建议先方格。
6. 街道图 A* 是否第一版就做，还是先做手绘路线。
